# 03 监控对象与采集约束

## 1. 第一优先监控对象

当前唯一最高优先监控对象是：

> 指定进程下的所有窗口。

包括但不限于：

- 主窗口
- 子窗口
- 弹窗
- 新开窗口
- 后台窗口
- 被遮挡窗口
- 折叠窗口
- 最小化窗口

## 2. 采集目标

目标不是只监控当前前台可见窗口，而是尽可能覆盖指定进程全窗口的可观测变化。

## 3. 必须拆开的两个概念

第一阶段必须明确区分：

- 窗口状态可观测
- 窗口像素可采集

这两个概念不能混用。

## 4. 采集层职责

采集层负责：

- 枚举进程关联窗口
- 跟踪窗口新增、关闭、隐藏、最小化和层级变化
- 尝试对目标窗口进行周期性采样
- 记录采样成功、失败和不可见状态
- 对无法直接采集像素的窗口保留状态事件

## 5. 最小化和折叠窗口约束

“最小化窗口也要尽量检测到”是核心产品要求，但第一阶段必须承认现实限制：

- 某些窗口状态下可以拿到元数据，但拿不到实时像素
- 某些状态下只能间接采样
- 某些应用后台渲染策略可能导致窗口不可直接观测

因此第一阶段原则如下：

1. 先保证窗口状态感知
2. 能采像素时再进入变化识别
3. 不能采像素时至少写入状态变化事件
4. 恢复可采集后尽快补齐变化分析

## 6. 第一阶段采集结论

第一阶段产品承诺不是“任何最小化窗口都能稳定拿到实时像素”，而是：

- 尽量提升全窗口可观测性
- 明确记录窗口状态
- 把可观测性纳入事件模型
- 避免对不可采集状态做虚假承诺
