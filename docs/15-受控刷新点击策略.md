# 15 受控刷新点击策略

## 1. 文档目标

本文件定义 Ayes 第一阶段的受控刷新点击能力。

它覆盖：

- 点击点选择方式
- 配置结构
- 执行频率
- 暂停与恢复
- 安全边界
- 审计事件

## 2. 能力定位

受控刷新点击不是通用自动化能力。

它只服务于以下监控任务：

- 某些页面刷新后才能暴露状态变化
- 某些页面需要定时点刷新按钮
- 状态页需要周期查询

第一阶段不允许把它扩展为：

- 任意流程自动化
- 多步点击编排
- 文本输入
- 任意键盘控制
- 自主决策型 RPA

## 3. 用户选点方式

点击点必须由用户显式选择。

第一阶段建议方式：

1. 用户先选择监控窗口或屏幕
2. 系统展示当前画面预览
3. 用户在预览图上点击一个刷新点
4. 系统记录该点的坐标和坐标空间

记录内容至少包括：

- `x`
- `y`
- `coordinate_space`
- `target_id`
- `window_id` 或 `screen_id`

## 4. 坐标空间

第一阶段必须支持：

- `window`
- `screen`

规则：

- 绑定窗口时优先使用窗口坐标空间
- 绑定整屏时使用屏幕坐标空间
- 点击点必须和当前监控目标绑定

## 5. 配置结构

`watch spec.actions.refresh_click` 建议结构如下：

```json
{
  "enabled": false,
  "point": {"x": 0, "y": 0},
  "coordinate_space": "window|screen",
  "interval_sec": 30,
  "cooldown_sec": 30,
  "max_clicks_per_hour": 120,
  "pause_when_target_matched": true
}
```

字段语义：

- `enabled`：是否启用
- `point`：用户选定点击点
- `coordinate_space`：坐标空间
- `interval_sec`：定时点击间隔
- `cooldown_sec`：最小点击间隔保护
- `max_clicks_per_hour`：上限保护
- `pause_when_target_matched`：命中目标后是否暂停点击

## 6. 执行策略

执行必须遵守：

- 到达 `interval_sec` 才允许尝试点击
- 未超过 `cooldown_sec` 时不得重复点击
- 超过 `max_clicks_per_hour` 时必须自动暂停
- 监控目标不可观测时不得盲点
- 窗口或屏幕绑定失效时不得继续点击

对于最小化窗口，第一阶段必须明确：

- 不默认承诺最小化状态下仍可稳定点击
- 只有当平台实现已经验证“最小化状态下仍可稳定定位并执行点击”时，才允许启用
- 如果做不到，系统必须给出约束：需要先恢复窗口、激活窗口，或该状态下不支持点击

## 7. 暂停与恢复

第一阶段必须支持以下暂停条件：

- 用户手动关闭
- 命中触发目标且 `pause_when_target_matched = true`
- 点击次数达到 `max_clicks_per_hour`
- 当前目标不可观测
- 目标窗口或屏幕失效

恢复方式：

- 用户手动恢复
- 重新选择监控目标
- 重新启用 `refresh_click`

## 8. 与任务模式的关系

### 8.1 triggered

在 `triggered` 模式中，刷新点击常用于：

- 刷新目标状态页面
- 刷新需要周期查询的页面
- 刷新状态页直到命中目标
- 刷新数值页面直到满足阈值条件

建议：

- 命中目标后默认暂停点击
- 命中目标后写入点击相关事件和触发事件

### 8.2 observe

在 `observe` 模式中，也允许启用受控刷新点击。

适用场景：

- 用户没有告警要求，但希望页面保持刷新状态
- 用户稍后会对变化进行提问

规则：

- 不因 observe 模式而禁止刷新点击
- 但仍然必须遵守同样的频控和审计规则

## 9. 审计事件

刷新点击必须进入事件流。

建议事件类型：

- `refresh_click`
- `refresh_click_skipped`
- `refresh_click_paused`
- `refresh_click_resumed`

典型原因：

- 已执行点击
- 冷却期内跳过
- 不可观测而跳过
- 用户关闭而暂停
- 命中目标后自动暂停

## 10. 与告警和问答的关系

刷新点击后的变化可能触发：

- `text_change`
- `semantic_match`
- `alert_sent`

问答时应允许说明：

- 是否启用了刷新点击
- 是否最近执行过刷新点击
- 某次目标命中是否发生在刷新点击之后

## 11. 安全边界

第一阶段必须明确限制：

- 只允许单点点击
- 只允许用户选定点
- 不允许自动寻找按钮
- 不允许自动输入文本
- 不允许多步工作流
- 不允许根据模型自由推理执行任意点击
- 不允许在未验证的平台/窗口状态下假装支持最小化窗口点击

## 12. 第一阶段结论

受控刷新点击是监控任务的辅助动作，不是通用自动化。

它必须：

- 用户显式选点
- 频率可配置
- 可暂停和恢复
- 可审计
- 与事件、告警和问答链路联动
