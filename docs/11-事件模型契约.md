# 11 事件模型契约

## 1. 文档目标

事件是 Ayes 时间线、告警、问答和后续 skill 接入的共同数据基础。

本文件定义：

- 事件基础字段
- 事件类型
- 事件来源
- 优先级和置信度
- 可观测性字段
- 证据引用
- 审计事件

后续实现不得绕过事件模型直接把原始截图或 OCR 结果暴露给问答链路。

## 2. 事件设计原则

- 所有可被问答、告警、回放使用的信息都必须落成事件
- 事件必须可排序、可检索、可引用
- 事件必须绑定任务、目标、窗口或屏幕
- OCR、动作、告警、窗口生命周期都应统一进入事件流
- 短期详细记忆和长期轻量记忆共用同一事件基础模型

## 3. 基础事件结构

```json
{
  "event_id": "evt_xxx",
  "task_id": "task_xxx",
  "spec_version": "1.0",
  "task_mode": "triggered|observe",
  "timestamp": 0,
  "source": "capture|diff|ocr|tagger|semantic_match|action|alert|system",
  "event_type": "text_change",
  "priority": "low|medium|high",
  "confidence": 0.0,
  "target": {
    "type": "process|window|screen",
    "process_name": "TargetApp",
    "process_id": null,
    "window_id": null,
    "screen_id": null,
    "window_title": "",
    "window_state": "visible|hidden|minimized|occluded|closed|unknown"
  },
  "observability": {
    "has_metadata": true,
    "has_pixels": true,
    "is_onscreen": true,
    "is_observable_candidate": true,

    "x": 0,

  },

```

## 4. 事件类型

第一阶段至少支持以下事件类型：

- `window_lifecycle`
- `capture_status`
- `visual_change`
- `text_change`
- `status_change`
- `dialog`
- `error_like`
- `notification_like`
- `captcha_like`
- `semantic_match`
- `refresh_click`
- `alert_sent`
- `alert_suppressed`
- `summary_generated`

## 5. 事件来源

`source` 用于说明事件来自哪个处理阶段：

- `capture`：采集层
- `diff`：变化检测层
- `ocr`：OCR 层
- `tagger`：轻量视觉标签层
- `semantic_match`：语义匹配层
- `action`：受控动作层
- `alert`：告警层
- `system`：系统状态或生命周期事件

## 6. 优先级

优先级建议分为：

- `low`
- `medium`
- `high`

建议规则：

- 普通视觉变化：`low`
- 命中监控意图但证据不强：`medium`
- 明确命中触发目标、错误、验证码、断连、库存恢复：`high`

## 7. 可观测性字段

可观测性必须作为一等字段。

原因：

- 指定进程下可能存在无画面窗口
- 最小化、遮挡、后台窗口不一定都能抓取像素
- 问答时必须能解释“为什么没有更详细信息”

关键字段：

- `has_metadata`
- `has_pixels`
- `is_onscreen`
- `is_observable_candidate`
- `capture_status`

## 8. Watch Match

`watch_match` 表示事件是否命中当前监控目标。

适用于：

- 商品有货
- 验证码出现
- 登录失效
- 报错
- 断连

要求：

- `matched` 表示是否命中
- `score` 保存语义匹配或规则匹配分数
- `matched_query` 保存命中的语义查询
- `matched_rule` 保存命中的规则

## 9. 证据引用

事件不应直接内嵌大图。

证据通过 `evidence_refs` 引用：

- 全屏截图
- 窗口截图
- ROI 切片
- OCR 原始结果

证据文件由存储层管理生命周期。

## 10. 受控动作事件

刷新点击必须进入事件流。

示例：

```json
{
  "event_type": "refresh_click",
  "source": "action",
  "summary": "执行一次用户配置的刷新点击",
  "region": {"x": 100, "y": 200, "w": 1, "h": 1},
  "tags": ["action", "refresh_click"]
}
```

## 11. 告警事件

告警发送和抑制都要进入事件流。

原因：

- 用户可以追问“为什么刚才没有通知我”
- 长期轻量记忆需要保留告警轨迹

事件类型：

- `alert_sent`
- `alert_suppressed`

## 12. 与记忆层的关系

短期详细记忆保存高密度事件和证据引用。

长期轻量记忆保存：

- 高优先级事件
- 告警事件
- 阶段摘要
- 关键状态变化

## 13. 第一阶段结论

事件模型是 Ayes 的核心数据契约。

所有截图、OCR、语义匹配、告警、刷新点击和窗口状态变化都必须先归一化成事件，再进入时间线、问答或告警链路。
