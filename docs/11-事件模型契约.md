# 11 事件模型契约

## 1. 文档目标

事件是 Ayes 时间线、告警、问答和后续 skill 接入的共同数据基础。

本文件定义：

- 事件基础字段
- 事件类型
- 事件来源
- 优先级和置信度
- 可观测性字段
- 证据引用
- 审计事件

后续实现不得绕过事件模型直接把原始截图或 OCR 结果暴露给问答链路。

## 2. 事件设计原则

- 所有可被问答、告警、回放使用的信息都必须落成事件
- 事件必须可排序、可检索、可引用
- 事件必须绑定任务、目标、窗口或屏幕
- 事件必须尽量保留区域、坐标和前后变化关系
- OCR、动作、告警、窗口生命周期都应统一进入事件流
- 短期详细记忆和长期轻量记忆共用同一事件基础模型

## 4. 事件类型

第一阶段至少支持以下事件类型：

- `window_lifecycle`
- `capture_status`
- `visual_change`
- `visual_summary`
- `text_change`
- `status_change`
- `dialog`
- `error_like`
- `notification_like`
- `captcha_like`
- `semantic_match`
- `refresh_click`
- `refresh_click_skipped`
- `refresh_click_paused`
- `refresh_click_resumed`
- `alert_sent`
- `alert_suppressed`
- `alert_failed`
- `summary_generated`

## 5. 事件来源

`source` 用于说明事件来自哪个处理阶段：

- `capture`：采集层
- `diff`：变化检测层
- `ocr`：OCR 层
- `tagger`：轻量视觉标签层
- `semantic_match`：语义匹配层
- `action`：受控动作层
- `alert`：告警层
- `system`：系统状态或生命周期事件

## 6. 优先级

优先级建议分为：

- `low`
- `medium`
- `high`

建议规则：

- 普通视觉变化：`low`
- 命中监控意图但证据不强：`medium`
- 明确命中触发目标、错误、验证码、断连、库存恢复：`high`

## 7. 可观测性字段

可观测性必须作为一等字段。

原因：

- 指定进程下可能存在无画面窗口
- 最小化、遮挡、后台窗口不一定都能抓取像素
- 问答时必须能解释“为什么没有更详细信息”

关键字段：

- `has_metadata`
- `has_pixels`
- `is_onscreen`
- `is_observable_candidate`
- `capture_status`

## 8. Watch Match

`watch_match` 表示事件是否命中当前监控目标。

适用于：

- 目标状态满足条件
- 数值满足阈值条件
- 验证码出现
- 登录失效
- 报错
- 断连

要求：

- `matched` 表示是否命中
- `score` 保存语义匹配或规则匹配分数
- `matched_query` 保存命中的语义查询
- `matched_rule` 保存命中的规则
- 如果命中的是数值规则，还应补充：
  - `matched_value`：实际识别到的命中数值
  - `matched_unit`：当前规则或文本中的单位
  - `matched_field`：命中的业务字段，例如 `price`、`stock`、`latency`

这样前端、问答链路和后续 Agent 才能稳定回答：

- 命中了哪个值
- 这个值大概是多少
- 命中的是什么字段
- 该值来自哪个事件、哪个 ROI、哪个时间点

## 9. 证据引用

事件不应直接内嵌大图。

证据通过 `evidence_refs` 引用：

- 全屏截图
- 窗口截图
- ROI 切片
- OCR 原始结果

证据文件由存储层管理生命周期。

## 9.1 区域与坐标语义

第一阶段事件必须支持：

- 区域 id
- 区域名称
- 像素坐标
- 归一化坐标
- 坐标空间

原因：

- 多 ROI 监控必须能区分事件来自哪个区域
- 问答时需要回答“哪个位置发生了什么变化”
- 大模型需要知道画面语义与位置关系，而不是只拿到一段 OCR 文本

建议：

- `coordinate_space` 默认使用 `target`
- `x_norm / y_norm / w_norm / h_norm` 用于跨分辨率重放和前端回显

## 9.2 非文本视觉摘要

当视觉增强层介入时，事件应补充 `visual` 字段。

用途：

- 记录图标、图表、颜色状态、按钮显隐、弹窗结构等非文本信息
- 为问答提供比 OCR 文本更接近画面语义的描述

要求：

- 视觉摘要必须简短、结构化
- 必须标注 provider
- 不能把大段原始模型输出直接塞入事件主字段

## 10. 受控动作事件

刷新点击必须进入事件流。

示例：

```json
{
  "event_type": "refresh_click",
  "source": "action",
  "summary": "执行一次用户配置的刷新点击",
  "region": {"x": 100, "y": 200, "w": 1, "h": 1},
  "tags": ["action", "refresh_click"]
}
```

第一阶段还应支持：

- `refresh_click_skipped`
- `refresh_click_paused`
- `refresh_click_resumed`

## 11. 告警事件

告警发送和抑制都要进入事件流。

原因：

- 用户可以追问“为什么刚才没有通知我”
- 长期轻量记忆需要保留告警轨迹

事件类型：

- `alert_sent`
- `alert_suppressed`
- `alert_failed`

## 12. 与记忆层的关系

短期详细记忆保存高密度事件和证据引用。

长期轻量记忆保存：

- 高优先级事件
- 告警事件
- 阶段摘要
- 关键状态变化

## 13. 第一阶段结论

事件模型是 Ayes 的核心数据契约。

所有截图、OCR、语义匹配、告警、刷新点击和窗口状态变化都必须先归一化成事件，再进入时间线、问答或告警链路。
