# 18 Web 工作台与人类测试界面

## 1. 文档目标

本文件定义 Ayes 下一阶段必须实现的本地 Web 工作台。

目标不是做宣传页，而是做一个：

- 人类用户可直接使用
- 可直接观察监控效果
- 可直接查看记忆、事件、日志
- 可直接测试问答与条件监控

的工作台界面。

## 2. 定位

Web 工作台是 Ayes 当前阶段的人类主入口。

它必须承担：

- 目标选择
- 监控任务配置
- 监控启动与停止
- 近期事件查看
- 短期记忆查看
- 问答测试
- 运行状态查看
- 日志查看入口

## 3. 布局原则

前端必须：

- 简洁
- 高信息密度
- 少卡片
- 强一体感

推荐结构：

1. 左侧：目标与任务区
2. 中间：近期事件时间线 / 当前截图预览 / 记忆查看
3. 右侧：问答区 / 日志区 / 状态区

页面应优先使用：

- 分栏
- 表格
- 列表
- 时间线
- 分割线
- 抽屉 / 折叠面板

不推荐：

- 卡片瀑布流
- 组件堆砌式 dashboard
- 营销页式大块留白

但必须明确：

- 需要保留当前已有的目标选择、任务配置、运行状态、事件、截图、问答、日志等模块
- 风格层应优先吸收以下特征：
  - 克制的黑白灰主色
  - 连续纸面感背景
  - pill 化按钮、输入框和筛选控件
  - 极少装饰、少阴影、细分割线
  - 通过字重、字号、边线和留白建立层级

不应照搬的部分：

- 营销型 hero
- 说明式首页排版
- 低信息密度的大段居中排版

工作台落地要求：

- 保持三栏工作台结构
- 保持高信息密度，但视觉上更平静、更轻、更连贯
- 重要操作按钮、任务输入区、日志与时间线应在同一视觉系统下统一

## 4. MVP 必做界面模块

### 4.1 目标选择区

- 查看屏幕候选
- 查看进程候选
- 显示预览、进程名、代表窗口标题、可观测状态
- 点击绑定监控目标
- 对低分辨率辅助候选默认折叠，用户按需展开
- 支持像共享屏幕软件一样，优先通过预览图判断“是不是我想监控的对象”
- 进程级选择也必须显示代表性窗口快照，不能只显示进程名
- 不再单独铺设窗口候选主列表，避免与进程候选重复；如需单窗口监控，应在选定进程候选后切换到“监控当前窗口”模式

### 4.2 任务配置区

- 选择 observe / triggered
- 调整采样频率
- 配置关键词或简单触发条件
- 配置是否启用 webhook
- 配置是否启用 refresh_click
- 显示当前已绑定目标摘要
- 支持将当前界面配置直接转成 watch spec 并装载

### 4.3 运行控制区

- 启动监控
- 停止监控
- 显示运行中 / 已停止 / 异常
- 显示当前任务绑定目标
- 主视图状态摘要应尽量集中显示最近 OCR 质量、最近视觉决策和最近视觉结果，减少用户必须在多个面板间来回对照
- 主视图状态摘要还应继续承担“首屏诊断条”职责，除运行状态外，至少还应尽量集中显示当前实际采集目标、最近采集状态、最近命中、最近告警、最近记忆条目数和最近日志健康信号，便于用户第一眼判断“有没有在看、正在看哪一个窗口、看得准不准、最近有没有触发过、最近有没有出错”

### 4.4 近期事件区

- 展示最近事件时间线
- 支持查看事件类型、时间、摘要、目标、优先级
- 支持查看 OCR 文本摘要
- 支持查看 OCR 质量摘要，至少包括 provider、字符数、块数、平均置信度和是否稀疏
- 如果事件包含块级位置结构，应直接显示区域名和大致位置摘要，而不是只暴露原始 bbox

### 4.5 短期记忆区

- 展示最近几分钟的结构化记忆
- 支持按关键词过滤
- 支持按最近 N 分钟过滤
- 在问答命中证据事件中，如果已具备位置摘要，应直接用于人工核验
- 除问答结果外，还应直接显示“最近记忆条目”列表，让用户在不提问时也能查看最近几分钟内被保留下来的关键事件
- 最近记忆条目应尽量复用事件时间、摘要、位置摘要和证据预览，而不是单独发明另一套不可核验的数据格式

### 4.6 问答区

- 输入问题
- 返回结构化回答
- 显示命中事件与证据引用
- 显示使用的时间范围
- 如果问题命中了数值或规则类事件，问答区应直接显示结构化命中摘要，例如：
  - 命中字段
  - 命中值
  - 单位
  - 命中规则
  - 区域名称
  - 人类可读时间

要求：

- 用户不应必须展开原始事件 JSON 才能看懂“到底命中了什么”
- 问答区的结构化摘要应优先服务人工核验和后续 Agent 消费
- 如果已存在可读时间和区域信息，应直接在问答摘要区展示，而不是只埋在下方事件明细中
- 如果命中了 vision 事件，问答区应额外显示视觉结构化摘要，包括视觉摘要、细节行、触发原因、模型名和区域信息，而不是只把这些信息埋在事件明细里

### 4.7 日志区

- 查看系统日志
- 查看监控任务日志
- 查看 OCR / capture / diff / alert 相关日志
- 查看 vision 相关触发与跳过原因
- 支持按日志类别过滤
- 支持按当前任务或指定任务查看

### 4.7.1 视觉轨迹区

- 单独查看 `vision_triggered` / `vision_skipped` 事件
- 直接显示触发原因、阻断原因、模型名、provider 和相关证据
- 如果视觉模型返回了多行结果，应尽量保留前几条细节行，而不是压扁成只有一句摘要
- 用于人工判断“为什么这次启用了视觉增强”以及“为什么当前轮次没有启用”

### 4.8 任务与时间范围区

- 可显式输入或切换任务 id
- 可设置最近 N 分钟范围
- 该时间范围必须实际作用于近期事件、问答与短期记忆读取
- 用户问“最近几分钟发生了什么”时，界面和接口都应遵守当前时间范围

## 5. 当前阶段验收要求

只有当以下内容成立时，Web 工作台才算达标：

- 用户无需命令行也能完成一次目标选择和监控启动
- 用户能直接看到近期事件
- 用户能直接看到短期记忆
- 用户能直接发起一次问答
- 用户能直接查看近期日志

当前实现还应至少包括：

- 当前截图预览
- 运行状态面板
- 屏幕目标一键加载
- 进程目标点击加载
- 一次执行采样按钮
- 停止监控按钮
- 最小任务配置表单

## 6. 与后续 Agent 接入的关系

Web 工作台只是人类入口。

它背后的监控、查询、日志和问答能力必须继续保持服务化边界，供后续：

- skill
- tool
- MCP
- agent

复用。

## 7. 当前实现校准

当前代码已落地第一版本地 Web 工作台：

- [web/static/app.css](/Users/apple/Desktop/2026/Ayes/web/static/app.css)

- [src/ayes/api/server.py](/Users/apple/Desktop/2026/Ayes/src/ayes/api/server.py)

当前已验证可用的页面链路：

- 加载屏幕监控任务
- 加载窗口监控任务
- 执行一次监控采样
- 查看近期事件
- 查看问答与短期记忆
- 查看近期日志
- 查看当前截图预览

这意味着当前阶段已经不再只有 CLI，而是具备了可直接人工测试的本地工作台入口。

当前数据来源也已从纯内存态开始过渡为：

- 当前运行状态：服务内状态
- 近期事件：SQLite + 当前任务读取
- 近期日志：SQLite + 当前任务读取
- 问答与短期记忆：当前短期记忆查询接口

后续仍需继续推进长期记忆和更多筛选能力，但工作台已经具备真实服务化读取链路。

当前工作台还新增了：

- 任务 id 输入框
- 最近 N 分钟时间范围输入
- 长期摘要视图
- 屏幕候选与进程候选双列表
- 最小 watch spec 配置区

这使得工作台开始具备：

- 显式任务切换准备
- 显式时间范围切换准备
- 长期/短期双层查看入口

后续这几个入口不能只停留在“有输入框”，而必须满足：

- 任务 id 切换后，近期事件、长期摘要、日志、问答都能按任务读取
- 最近 N 分钟切换后，近期事件和问答都能按时间范围收敛
- 问答结果应显示回答、命中证据、使用时间范围与记忆层
- 近期事件、OCR 片段、动作轨迹、命中轨迹、告警轨迹、长期摘要、日志区都应显式显示当前查询上下文，例如 `task_id / minutes / source|category / count`
- 长期摘要区还应支持显式 `hours` 范围输入，便于人工核验“最近 24 小时 / 48 小时 / 72 小时”的长期回顾链路，而不是只能看不带时间范围的最近摘要列表
- 当某个面板在当前过滤范围下没有结果时，界面应直接说明“当前范围内无结果”，而不是只留下空白列表

当前阶段下一批必须落地的能力：

- 目标选择区显示屏幕候选与进程候选两类对象
- 工作台提供最小 watch spec 配置面
- 用户无需命令行即可完成“选目标 -> 配置模式/频率/关键词 -> 装载任务 -> 执行一次”

当前实现校准补充：

- 已新增 `/api/targets`，统一返回屏幕候选和进程候选；如有需要，后端仍可保留窗口级元数据供 `window` 模式装载使用
- 已新增 `/api/watch/load-configured`，允许 Web 表单直接生成并装载 watch spec
- 当前工作台已支持“选主屏幕 -> 配置 observe/triggered、频率、关键词、webhook -> 装载任务 -> 执行一次”

当前阶段仍需继续补齐并应视为正式要求的能力：

- 用户无需命令行即可启动持续监控
- 工作台应明确区分“已装载任务”和“后台持续运行中”
- 停止按钮应能停止持续监控，而不是只清空当前任务状态

当前实现补充：

- 工作台已新增 OCR 片段区，用于直接查看最近识别文本，辅助配置 triggered 关键词
- 告警轨迹不再只是空容器，后端已开始生成真实的 `alert_sent` / `alert_failed` / `alert_suppressed` 事件
- 这意味着用户已经可以通过界面观察“最近识别到了什么文本”以及“是否真的尝试过发送告警”
- 工作台已新增运行状态摘要区，直接显示当前任务、运行状态、当前实际采集目标、最近采集状态、最近命中/告警和最近错误
- 运行状态摘要区当前已开始集中显示最近 OCR 质量、最近视觉决策和最近视觉结果，便于快速扫读当前链路健康度
- 下一阶段应继续把最近命中、最近告警、最近记忆和最近日志健康状态汇总进同一区域，避免用户必须依次打开事件、告警、记忆、日志四个面板才能判断链路是否健康
- 问答区已新增结构化摘要展示，直接显示结论、置信度、实际命中时间范围、证据事件数量和记忆层
- 近期事件、OCR 片段和问答证据事件应逐步直接展示 `区域 / 大致方位` 级别的位置摘要，降低人工核对 bbox 的成本
- 近期事件、OCR 片段、动作轨迹、命中轨迹、告警轨迹、长期摘要、近期日志等列表，当前已开始显式显示 `task_id / 时间范围 / 来源或类别 / 条数`，并在空结果时直接解释当前过滤上下文
- 问答与短期记忆区当前已新增“最近记忆条目”列表，可按当前任务、最近时间范围和关键词直接查看近期保留事件
- OCR 相关事件当前已开始附带轻量质量摘要，帮助用户快速判断“是否真的识别到了足够可靠的文本”
- 当视觉增强启用时，时间线中当前已开始出现 `vision_triggered` / `vision_skipped` 事件，帮助用户直接判断“为什么这次触发了视觉增强，或为什么没有触发”
- 当前工作台已新增独立“视觉轨迹”面板，便于集中查看 vision 审计事件，而不需要在总时间线中逐条翻找
- 当前工作台的视觉收口应继续严格参考 `00-前端设计参考DESIGN.md`，以白底、黑白灰、pill 几何、弱卡片和细分割线为主，但不得打散现有监控工作台的信息结构与功能模块

当前阶段新增正式要求：

- 进程候选列表不应把大量 `500x500` 或更小的辅助代表窗口直接铺满主区域
- `500x500` 及以下进程代表窗口默认进入折叠区
- 没有快照的进程候选默认折叠
- 屏幕与进程两类主目标都应尽可能显示真实快照
- 工作台必须显式展示当前后台是否仍在运行，以及当前前端连接数
- 当监控已经启动时，即使关闭当前页面，后台监控也必须继续运行
- 工作台应默认连接单实例后台服务，不得暗中重复拉起多个后台实例
- 后续前端视觉重构必须优先沿用当前模块和组件，只改风格表达，不先做功能删减

## 8. 当前人工测试步骤

当前版本可按以下步骤直接人工测试：

1. 启动本地服务并打开工作台首页
2. 在左侧“监控目标”中点击主屏幕或某个进程候选
3. 在“任务配置”中选择 `observe` 或 `triggered`，设置截图/OCR 频率并装载任务
4. 点击“执行一次”或“开始持续监控”
5. 在中间区域查看：
   - 当前截图预览
   - 近期事件
   - OCR 片段
   - 命中轨迹 / 告警轨迹
6. 在右侧输入“最近发生了什么”或关键词问题，检查：
   - 是否返回结构化结论
   - 是否显示时间范围
   - 是否显示证据事件
   - 是否显示记忆层
   - 是否显示“最近记忆条目”列表
7. 切换日志类别或任务范围，检查近期日志、近期事件和问答是否随之变化
