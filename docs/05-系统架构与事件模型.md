# 05 系统架构与事件模型

## 1. 系统模块

第一阶段系统拆分为以下模块：

- 目标进程与窗口发现层
- 采集层
- 变化检测层
- OCR 与文本结构化层
- 轻量视觉标签层
- 语义匹配层
- 事件抽取层
- 短时时间线存储层

## 2. 模块职责

### 2.1 目标进程与窗口发现层

- 识别指定进程
- 枚举关联窗口
- 跟踪窗口生命周期

### 2.2 采集层

- 周期性采样
- 记录采样可观测性
- 输出窗口状态

### 2.3 变化检测层

- 帧差分
- ROI 检测
- 文本块变化检测
- 静态区域跳过
- 相同内容去重

### 2.4 OCR 与文本结构化层

- 提取文字
- 清洗与结构化
- 绑定区域上下文

### 2.5 轻量视觉标签层

- 对变化结果做轻量标签归类

### 2.6 语义匹配层

- 判断事件与监控意图相关性

### 2.7 事件抽取层

- 将原始信号压缩为结构化事件

### 2.8 短时时间线存储层

- 保存最近 5-15 分钟事件
- 保存事件引用关系
- 支持检索

## 3. Watch Spec 建模

第一阶段围绕 `watch spec` 建模。

建议结构：

```json
{
  "target": {
    "type": "process",
    "process_name": "TargetApp",
    "include_all_windows": true
  },
  "sampling": {
    "interval_ms": 1500,
    "retain_minutes": 15
  },
  "watch_intent": {
    "summary": "关注报错、验证码、断连、登录失效、长时间无响应"
  },
  "alert": {
    "enabled": true,
    "channel": "wecom_webhook",
    "priority_threshold": "medium",
    "cooldown_sec": 120
  }
}
```

## 4. 事件模型

第一阶段统一输出结构化 JSON 事件。

建议最小结构：

```json
{
  "event_id": "evt_xxx",
  "timestamp": 0,
  "process_name": "TargetApp",
  "window_id": "win_xxx",
  "window_title": "",
  "window_state": "visible|hidden|minimized|occluded|closed|unknown",
  "event_type": "text_change|status_change|dialog|error_like|notification_like|window_lifecycle",
  "priority": "low|medium|high",
  "confidence": 0.0,
  "matched_watch_intent": true,
  "region": {
    "x": 0,
    "y": 0,
    "w": 0,
    "h": 0
  },
  "ocr_text": "",
  "summary": "",
  "tags": ["ocr", "semantic_match"],
  "evidence_refs": ["snap_xxx", "roi_xxx"]
}
```

## 5. 存储原则

第一阶段只保留短时高价值时间线。

存储层重点是：

- 最近 5-15 分钟
- 事件为主
- 截图切片或证据引用为辅
- 支持按时间、窗口、标签、语义检索
