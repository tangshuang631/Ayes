# 19 日志、事件与记忆可视化

## 1. 文档目标

本文件定义 Ayes 当前阶段的可观测性和可视化查看要求。

重点不是“把日志写出来”，而是让用户和后续 Agent 都能明确知道：

- 刚才发生了什么
- 为什么发生
- 为什么没有发生

## 2. 必须可查看的对象

当前阶段至少必须可查看以下四类内容：

- 运行日志
- 近期事件
- 短期记忆
- 最近告警 / 命中记录

## 3. 日志分类

日志至少分为：

- `system`
- `watch`
- `capture`
- `diff`
- `ocr`
- `match`
- `alert`
- `action`
- `api`

## 4. 日志展示要求

前端中应支持：

- 查看最近日志
- 按类别过滤
- 按任务过滤
- 查看时间
- 查看摘要

当前阶段可以先不做复杂全文检索，但必须能让用户直观看到最近运行状态。

## 5. 近期事件展示要求

事件展示至少包括：

- 事件时间
- 事件类型
- 事件摘要
- 目标类型 / 目标标识
- OCR 文本摘要
- 是否命中监控条件

## 6. 短期记忆展示要求

短期记忆展示至少包括：

- 时间范围
- 最近 N 分钟
- 结构化回答摘要
- 关联事件列表
- 证据引用

## 7. 排查导向要求

可视化能力必须支持排查以下问题：

- 为什么没有识别到文字
- 为什么没有命中条件
- 为什么没有发 webhook
- 为什么当前窗口没有进入主监控链路
- 为什么最近问答没有结果

## 8. 与 API 的关系

日志、事件、记忆和最近命中记录都不应只存在前端局部状态。

必须保留统一查询接口，以便后续：

- Web 工作台读取
- CLI 调试
- Agent / skill 调用

## 9. 当前阶段结论

后续开发必须把“日志、事件、记忆可视化”视为正式交付内容，而不是调试附属品。

如果监控正在运行，但用户看不到近期事件、看不到短期记忆、看不到日志，就不能算真正可用。
