# 13 问答检索路径

## 1. 文档目标

本文件定义 Ayes 第一阶段的问答检索路径。

问答检索必须支持：

- 短期详细记忆查询
- 长期轻量记忆查询
- 关键词检索
- 向量语义检索
- 关键词 + 向量的混合检索
- triggered 和 observe 两种任务模式

## 2. 设计原则

- 问答必须基于事件和记忆，不直接全量重跑截图或 OCR
- 优先使用短期详细记忆回答最近 15 分钟内的问题
- 长期问题优先使用长期轻量记忆
- 检索必须保留证据引用
- 用户问“有没有出现某目标”时，要返回结论、时间、证据和置信度
- 重启服务或 skill 后，长期轻量记忆必须仍可检索
- 用户指定时间范围时，检索必须严格限制在该时间范围内

## 3. 问题类型

第一阶段至少支持以下问题类型：

- 最近 N 分钟发生了什么
- 最近 N 分钟有没有出现某个目标
- 某个触发目标是什么时候出现的
- 为什么现在变成这个界面
- 今天或最近几个小时大致发生了什么
- 最近几个小时是否触发过告警

## 4. 检索层选择

所有检索都必须先解析时间范围。

如果用户明确问“最近 1 小时”“最近 3 小时”“今天上午”等时间范围，则只允许检索该范围内的事件和摘要。

长期记忆保留 24-72 小时只是可用数据上限，不代表每次查询都要使用全部长期记忆。

### 4.1 短期详细问题

如果问题时间范围在最近 15 分钟内：

1. 查询短期详细记忆
2. 使用关键词 + 向量混合检索取候选事件
3. 补充 OCR 文本、区域、时间和证据引用
4. 生成细节回答

### 4.2 长期回顾问题

如果问题时间范围超过短期窗口：

1. 查询长期轻量记忆
2. 使用关键词 + 向量混合检索取摘要事件
3. 返回关键时间段、摘要、告警和高优先级事件

长期回顾问题必须遵守用户问题中的时间范围。

示例：

- 用户问“最近 3 小时有没有异常”，只能查最近 3 小时
- 即使长期记忆保留 72 小时，也不能把 3 小时前的异常混入回答

### 4.3 混合问题

如果问题同时涉及长期定位和短期细节：

1. 先查长期轻量记忆定位相关时间段
2. 如果相关时间段仍在短期窗口内，再查短期详细记忆
3. 合并长期摘要和短期证据

## 5. 混合检索策略

第一阶段检索策略固定为：

> 关键词检索 + 向量语义检索 + 时间范围过滤 + 任务目标过滤

其中时间范围过滤必须先于结果摘要和回答生成执行。

### 5.1 关键词检索

适合：

- 商品名
- “有货”
- “加入购物车”
- “验证码”
- “错误”
- “断开连接”
- 明确 OCR 文本

检索字段：

- `summary`
- `text.ocr_text`
- `text.normalized_text`
- `tags`
- `event_type`
- `watch_match.matched_query`
- `watch_match.matched_rule`

### 5.2 向量语义检索

适合：

- 用户表达和界面文案不完全一致
- “有没有可以买了”
- “是不是恢复库存了”
- “刚才是不是出问题了”
- “页面有没有变成登录失效”

向量对象：

- 事件摘要
- OCR 归一化文本
- 长期摘要
- watch intent
- 告警摘要

### 5.3 排序

候选结果排序建议综合：

- 时间接近度
- 关键词命中分
- 向量相似度
- 事件优先级
- 是否命中 watch intent
- 是否有证据引用

## 6. 回答结构

回答不应只输出自然语言段落。

建议结构：

```json
{
  "answer": "最近 5 分钟内未发现明确有货事件。",
  "confidence": 0.82,
  "time_range": {
    "from": 0,
    "to": 0
  },
  "matched_events": ["evt_xxx"],
  "evidence_refs": ["snap_xxx"],
  "memory_layers_used": ["short_term"],
  "time_scope_respected": true,
  "notes": ["未发现加入购物车或库存恢复相关文本"]
}
```

回答必须明确使用的时间范围，不能模糊成“历史上”或“曾经”。

## 7. triggered 模式问答

对于目标触发监控，问答应优先围绕 `watch_intent` 回答。

示例：

- 用户问：“这几分钟有货出现吗？”
- 系统应检索与“有货、加入购物车、立即购买、库存恢复”等相关事件
- 如果有结果，返回时间、证据、是否已 webhook
- 如果没有结果，说明未发现明确命中事件，并说明检索范围

## 8. observe 模式问答

对于观察型监控，问答没有预设触发目标。

系统应：

- 根据用户问题提取临时查询意图
- 在短期详细记忆中混合检索
- 必要时补充长期轻量记忆
- 返回最近变化、关键事件和证据引用

## 9. 重启后的长期记忆接续

长期轻量记忆必须持久化到 SQLite 或等价本地存储。

要求：

- 服务重启后可以继续查询之前的长期轻量记忆
- skill 重启后可以重新连接同一个任务的长期记忆
- watch task 需要稳定 `task_id`
- 长期摘要不能只存在内存中
- 清理只能按保留策略执行，不能因进程退出清空

## 10. 第一阶段结论

问答检索路径必须采用混合检索。

短期详细记忆负责最近 15 分钟内的高细节回答。

长期轻量记忆负责 24-72 小时内的低密度回顾，并且必须跨服务或 skill 重启持久化。

但任何问答都必须优先尊重用户指定的时间范围：问最近几小时就只查最近几小时，不能因为长期记忆存在更早数据而混入更早信息。
