# 13 问答检索路径

## 1. 文档目标

本文件定义 Ayes 第一阶段的问答检索路径。

问答检索必须支持：

- 短期详细记忆查询
- 长期轻量记忆查询
- 关键词检索
- 向量语义检索
- 关键词 + 向量的混合检索
- triggered 和 observe 两种任务模式

## 2. 设计原则

- 问答必须基于事件和记忆，不直接全量重跑截图或 OCR
- 优先使用短期详细记忆回答最近 15 分钟内的问题
- 长期问题优先使用长期轻量记忆
- 检索必须保留证据引用
- 用户问“有没有出现某目标”时，要返回结论、时间、证据和置信度
- 重启服务或 skill 后，长期轻量记忆必须仍可检索
- 用户指定时间范围时，检索必须严格限制在该时间范围内

## 3. 问题类型

第一阶段至少支持以下问题类型：

- 最近 N 分钟发生了什么
- 最近 N 分钟有没有出现某个目标
- 最近 N 分钟某个数值有没有低于某个阈值
- 最近 N 分钟某个文本、价格或提示大概出现在什么位置
- 某个触发目标是什么时候出现的
- 为什么现在变成这个界面
- 这几分钟某个软件有没有弹窗报错
- 今天某个股票是跌了还是涨了，最低大概是什么时候
- 今天或最近几个小时大致发生了什么
- 最近几个小时是否触发过告警
- 在没有显式重复上下文时，当前监控目标里刚才发生了什么

## 4. 检索层选择

所有检索都必须先解析时间范围。

如果用户明确问“最近 1 小时”“最近 3 小时”“今天上午”等时间范围，则只允许检索该范围内的事件和摘要。

长期记忆保留 24-72 小时只是可用数据上限，不代表每次查询都要使用全部长期记忆。

所有检索都必须先解析“当前监控上下文”。

如果用户没有重复说明对象，但当前任务已经绑定了：

- 某个进程
- 某个窗口
- 某个屏幕

则系统必须默认将该绑定目标作为问题上下文的一部分，而不是把问题当成无上下文开放查询。

### 4.1 短期详细问题

如果问题时间范围在最近 15 分钟内：

1. 查询短期详细记忆
2. 使用关键词 + 向量混合检索取候选事件
3. 补充 OCR 文本、区域、坐标、视觉摘要、时间和证据引用
4. 生成细节回答

### 4.2 长期回顾问题

如果问题时间范围超过短期窗口：

1. 查询长期轻量记忆
2. 使用关键词 + 向量混合检索取摘要事件
3. 返回关键时间段、摘要、告警和高优先级事件

长期回顾问题必须遵守用户问题中的时间范围。

示例：

- 用户问“最近 3 小时有没有异常”，只能查最近 3 小时
- 即使长期记忆保留 72 小时，也不能把 3 小时前的异常混入回答

### 4.3 混合问题

如果问题同时涉及长期定位和短期细节：

1. 先查长期轻量记忆定位相关时间段
2. 如果相关时间段仍在短期窗口内，再查短期详细记忆
3. 合并长期摘要和短期证据

### 4.4 隐式上下文问题

如果用户直接提问而没有重复监控对象，例如：

- “这几分钟有没有弹窗报错？”
- “今天是跌了还是涨了？”
- “最低大概是什么时候？”

则系统应：

1. 读取当前监控任务绑定的目标
2. 将该目标作为默认上下文
3. 在该上下文内做时间范围过滤和混合检索
4. 明确回答依据来自当前监控目标，而不是全局桌面

## 5. 混合检索策略

第一阶段检索策略固定为：

> 关键词检索 + 向量语义检索 + 时间范围过滤 + 任务目标过滤

其中时间范围过滤必须先于结果摘要和回答生成执行。

### 5.1 关键词检索

适合：

- 目标名
- “满足条件”
- “状态可用”
- “验证码”
- “错误”
- “断开连接”
- 明确 OCR 文本

检索字段：

- `summary`
- `text.ocr_text`
- `text.normalized_text`
- `tags`
- `event_type`
- `watch_match.matched_query`
- `watch_match.matched_rule`

### 5.2 向量语义检索

适合：

- 用户表达和界面文案不完全一致
- “有没有满足条件了”
- “是不是恢复正常了”
- “刚才是不是出问题了”
- “页面有没有变成登录失效”

向量对象：

- 事件摘要
- OCR 归一化文本
- 长期摘要
- watch intent
- 告警摘要

### 5.3 排序

候选结果排序建议综合：

- 时间接近度
- 关键词命中分
- 向量相似度
- 事件优先级
- 是否命中 watch intent
- 是否有证据引用

## 6. 回答结构

回答不应只输出自然语言段落。

建议结构：

```json
{
  "answer": "最近 5 分钟内未发现明确命中目标的事件。",
  "confidence": 0.82,
  "time_range": {
    "from": 0,
    "to": 0
  },
  "matched_events": ["evt_xxx"],
  "evidence_refs": ["snap_xxx"],
  "memory_layers_used": ["short_term"],
  "time_scope_respected": true,
  "notes": ["未发现与目标条件显著相关的文本或摘要事件"]
}
```

回答必须明确使用的时间范围，不能模糊成“历史上”或“曾经”。

补充要求：

- 如果事件绑定了 ROI，回答应尽量说明变化发生在哪个区域
- 如果 OCR 文本块带有位置结构，位置类问题应优先回答 ROI 名称和大致方向，例如 `左上`、`中间`、`右下`
- 对结构化命中结果，除 `field / value / unit / rule / region_name / time_text` 外，还应尽量补充 `location_summary`、首个文本块内容和首个文本块的大致方向或归一化坐标，减少“命中了但不知道屏幕上是哪一块”的信息损失
- 如果视觉增强层参与了事件生成，回答应可引用 `visual.summary`
- 如果用户问题显式涉及图像语义、图表、颜色、图标或按钮状态，检索层应优先考虑带 `visual` 字段的事件
- 如果回答中涉及时间点，优先返回人类可读时间表达，而不是直接暴露原始 Unix 时间戳
- 在当前阶段如果无法提供完整日期，也至少应输出 `HH:MM:SS` 级别的可读时间，便于人工核验截图、事件和问答是否对得上
- 问答结果除 `time_range` 外，还应尽量直接暴露“首条证据事件时间”与“当前截图参考时间”，帮助用户快速判断这次回答究竟主要依据了哪一轮证据
- 如果问答区同时展示当前截图参考，则应允许用户直接对比“当前截图时间”和“命中事件时间范围”是否一致，避免把旧截图误当成这次回答的直接依据

## 7. triggered 模式问答

对于目标触发监控，问答应优先围绕 `watch_intent` 回答。

示例：

- 用户问：“这几分钟有没有命中目标？”
- 系统应检索与当前 `watch_intent` 相关的文本、数值和摘要事件
- 如果有结果，返回时间、证据、是否已 webhook
- 如果没有结果，说明未发现明确命中事件，并说明检索范围

同时也应支持未显式重复目标的提问，只要该问题仍然围绕当前监控对象。

## 8. observe 模式问答

对于观察型监控，问答没有预设触发目标。

系统应：

- 根据用户问题提取临时查询意图
- 在短期详细记忆中混合检索
- 必要时补充长期轻量记忆
- 返回最近变化、关键事件和证据引用

如果用户没有补充上下文，则默认使用当前监控目标作为查询上下文。

## 9. 重启后的长期记忆接续

长期轻量记忆必须持久化到 SQLite 或等价本地存储。

要求：

- 服务重启后可以继续查询之前的长期轻量记忆
- skill 重启后可以重新连接同一个任务的长期记忆
- watch task 需要稳定 `task_id`
- 长期摘要不能只存在内存中
- 清理只能按保留策略执行，不能因进程退出清空

## 10. 第一阶段结论

问答检索路径必须采用混合检索。

短期详细记忆负责最近 15 分钟内的高细节回答。

长期轻量记忆负责 24-72 小时内的低密度回顾，并且必须跨服务或 skill 重启持久化。

但任何问答都必须优先尊重用户指定的时间范围：问最近几小时就只查最近几小时，不能因为长期记忆存在更早数据而混入更早信息。

## 11. 当前 MVP 实现校准

当前代码已先打通最小可人工测试问答链路：

- 监控执行一次或多次
- OCR 事件写入短期记忆
- 对最近 N 分钟做关键词过滤查询

- [src/ayes/cli/main.py](/Users/apple/Desktop/2026/Ayes/src/ayes/cli/main.py)

当前 MVP 问答能力边界：

- 已支持：最近几分钟内是否出现某关键词相关 OCR 事件
- 已支持：无关键词时返回最近短期事件摘要
- 已开始补齐：基于显式 `hours` 时间范围的长期摘要问答与回放
- 未完成：向量检索、复杂时间表达解析、隐式目标多任务上下文切换、长期摘要到细粒度事件的混合补查

因此当前 MVP 的定位是：

> 先让用户可以真实启动一次监控，看到 OCR 事件写入，并对最近短期记忆发起一次最小可验证问答。

后续收口方向补充：

- 当用户显式传入超过 15 分钟的问题时间范围时，问答链路应优先切换到长期轻量记忆层
- 长期问答必须返回实际使用的时间范围，并严格限制在该范围内
- 即使当前仍未完成向量检索，也不能把超过短期窗口的问题继续错误地压回短期记忆回答
