# 17 监控目标选择交互

## 1. 文档目标

本文件定义 Ayes v1 的监控目标选择交互。

目标是让用户像使用共享屏幕软件一样，通过预览画面直接选择：

- 整个屏幕
- 单个窗口
- 指定进程下的业务窗口

## 2. 交互目标

目标选择交互必须满足：

- 用户不需要理解系统窗口结构
- 用户不需要直接操作进程 id 或窗口 id
- 用户可以通过预览画面判断自己要监控什么
- 用户可以快速看出哪些目标当前可观测
- 用户可以一眼区分整个屏幕和窗口目标

## 3. 候选目标来源

候选目标列表由以下两类组成：

- 屏幕候选
- 窗口候选

### 3.1 屏幕候选

每个屏幕候选至少显示：

- 屏幕预览图
- 屏幕名称或编号
- 分辨率
- 当前是否可采集

### 3.2 窗口候选

每个窗口候选至少显示：

- 窗口预览图
- 进程名
- 窗口标题或可读标签
- 是否当前可观测
- 是否属于业务窗口候选

## 4. 列表排序

窗口候选应优先按业务价值排序，而不是按系统返回顺序原样展示。

建议排序优先级：

1. 当前可观测且有画面的业务窗口
2. 当前可观测但标题不清晰的窗口
3. 不可观测但仍保留元数据的窗口
4. 明显辅助或装饰性窗口

## 5. 过滤规则

目标选择界面默认应隐藏或弱化以下对象：

- 极小的辅助窗口
- 明显无画面的窗口
- 装饰性窗口
- 重复或无业务意义的系统附属窗口

但如果用户显式切换到“显示全部”，可以展示完整候选集合。

## 6. 候选目标卡片信息

每个候选项建议统一显示：

- 预览图
- 主标题：进程名或屏幕名
- 副标题：窗口标题、目标类型、分辨率或状态
- 可观测状态标记
- 是否推荐选择标记

## 7. 可观测状态标记

第一阶段至少需要显示以下状态：

- `可观测`
- `部分可观测`
- `仅有元数据`
- `当前不可采集`

作用：

- 帮助用户理解为什么某些窗口不能稳定监控
- 降低最小化、后台、辅助窗口造成的误解

## 8. 绑定流程

### 8.1 屏幕绑定

1. 用户选择某个屏幕候选
2. 系统生成 `target.type = screen`
3. 写入对应 `screen_id`
4. 进入 watch spec 配置或监控启动流程

### 8.2 窗口绑定

1. 用户选择某个窗口候选
2. 系统读取对应进程、窗口、可观测性信息
3. 生成 `target.type = window` 或 `target.type = process`
4. 进入 watch spec 配置或监控启动流程

### 8.3 进程绑定

如果用户希望“盯住这个软件”，而不是只盯一个窗口，则：

1. 用户从窗口候选中选择某个业务窗口
2. 系统提供“只监控当前窗口”与“监控该进程相关业务窗口”两种后续选项
3. 如果选择进程级监控，则生成 `target.type = process`

## 9. 与受控刷新点击的关系

当用户后续配置 `refresh_click` 时：

1. 必须先有已绑定的窗口或屏幕目标
2. 基于当前目标展示预览图
3. 用户在该预览图上选择点击点

因此目标选择交互和刷新点击交互必须共用同一套预览与坐标体系。

## 10. 与隐式上下文问答的关系

监控目标一旦绑定成功，后续问答就默认带入该目标。

这意味着目标选择交互不仅决定采集对象，也决定后续：

- 问答上下文
- 告警上下文
- 刷新点击上下文

## 11. 第一阶段结论

目标选择交互必须以预览画面为中心，而不是以底层 id 为中心。

它的本质是把系统级窗口和屏幕对象，转换成用户能直观看懂、能直接点击绑定的监控目标。
