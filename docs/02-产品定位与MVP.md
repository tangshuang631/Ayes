# 02 产品定位与 MVP

## 1. 项目定位

Ayes 是一个面向人类用户和 AI Agent 的视觉时序回放引擎。

它不是“当前屏幕问答器”，也不是“全量 OCR 工具”，而是一个将指定目标界面变化压缩为结构化事件流的系统。

## 2. 第一阶段目标

第一阶段目标如下：

- 长期监控指定进程下的所有窗口
- 支持用户以可视化方式选择要绑定的窗口或整个屏幕
- 支持带目标触发条件的长期监控
- 支持无触发条件的持续观察和随问随查
- 只识别有价值变化
- 保留最近 5-15 分钟短时时间线
- 保留更长时间的轻量长期时间线
- 支持用户提问最近几分钟发生了什么
- 支持企业微信 webhook 推送重点变化

## 3. 第一阶段主用户

第一阶段优先服务：

- 人类用户自己提问回放

不是第一阶段重点的内容：

- 多 Agent 编排
- 大而全的自动化平台
- 通用视觉理解平台

## 4. 产品边界

第一阶段不是：

- 通用桌面自动化平台
- 传统录屏软件
- 全桌面无差别记忆系统
- 复杂工作流系统

第一阶段要做的是：

- 面向指定进程
- 面向短时历史
- 面向重要变化
- 面向结构化事件
- 面向回放与提问
- 面向真正有可观测画面的业务窗口
- 面向用户可理解、可点击选择的监控目标
- 面向 Agent 可调用的长期视觉任务

## 5. MVP 必做范围

- 指定进程监控
- 进程关联窗口发现
- 画面化窗口/屏幕选择
- 简洁可用的本地 Web 工作台
- 长时运行
- 周期性采样
- 差分检测
- OCR 文本抽取
- 轻量视觉标签
- 语义匹配
- 时间线事件存储
- 短期详细记忆 + 长期轻量记忆
- 近期事件查看
- 短期记忆查看
- 运行日志查看
- 企业微信 webhook 告警
- 用户问答回放
- 受控刷新点击能力

## 6. MVP 不做范围

- YOLO 训练与复杂检测模型
- 全桌面监控
- 通用鼠标键盘自动操作
- 长期历史无限存储
- 复杂多 Agent 编排
- 通用多模态大模型平台化

## 7. 第一阶段任务模式

第一阶段必须支持两种任务模式。

### 7.1 目标触发监控

用户或 Agent 提供一个明确目标，例如：

- 某个目标状态出现时通知我
- 某个数值低于或高于阈值时通知我
- 页面出现验证码时通知我
- 出现错误、断连、登录失效时通知我

执行流程：

1. 用户选择监控窗口、进程或屏幕
2. Agent 将自然语言目标转换为 `watch spec`
3. Ayes 进入长期监控
4. Ayes 持续维护短期详细记忆和长期轻量记忆
5. 命中触发条件时发送企业微信 webhook
6. 用户提问“刚才几分钟内有没有命中目标”时，优先查询短期详细记忆回答

### 7.2 观察型监控

用户或 Agent 不提供触发和通知要求，只要求：

- 帮我开始持续监控这个屏幕
- 帮我观察这个进程
- 先盯着这个窗口，后面我随时问你

执行流程：

1. 用户选择监控窗口、进程或屏幕
2. Ayes 持续采集变化并维护时间线
3. 不主动推送 webhook
4. 用户提问时直接进入短期详细记忆和长期轻量记忆检索链路

## 8. 受控刷新点击边界

第一阶段可以支持“受控刷新点击”，用于商品库存、抢购页面、状态页等需要周期刷新才能暴露变化的场景。

该能力必须满足：

- 点击点由用户明确选择
- 点击目标绑定到具体窗口或屏幕坐标
- 点击频率可配置
- 点击能力可关闭
- 点击动作必须记录到时间线
- 默认不做任意自动操作规划

因此它不是通用 RPA，也不是自主鼠标键盘控制，只是为监控任务服务的受控辅助动作。

完整策略见：

- [15-受控刷新点击策略.md](/Users/apple/Desktop/2026/Ayes/docs/15-受控刷新点击策略.md)

商品库存、价格提醒、抢购页面只是典型示例，不构成 Ayes 的产品边界。Ayes 的目标是通用视觉条件监控、条件触发告警和可提问视觉记忆。

## 9. 当前阶段补充边界

当前阶段即使已经具备最小 CLI MVP，也不能把 CLI 当作最终唯一交付形态。

接下来必须补齐：

- 面向 Codex / Agent 的本地 skill 与稳定 API / CLI 工具层
- 人类用户可直接使用的轻量本地 Web 工作台
- 近期事件、短期记忆、日志和当前运行状态的可视化查看
- 面向后续 Agent 接入的 API 化边界

原因：

- 没有 skill / 工具层时，很难直接把 Ayes 变成 Agent 的眼睛
- 没有界面时，人类用户很难判断效果
- 没有事件和记忆可视化时，很难验证监控是否真正工作
- 没有日志时，很难排查为什么没抓到、没命中、没告警

因此当前阶段的重点不再只是“继续补底层链路”，而是：

> 把已有核心能力同时包装成：
>
> - Agent 可直接调用的 skill / tool / API
> - 人类可直接配置和核验的轻量工作台

## 10. 当前默认使用路径

当前默认使用路径正式定义为：

1. 人类先通过轻量 Web 工作台完成：
   - 选择屏幕或进程目标
   - 选择一个或多个 ROI
   - 配置 observe / triggered / webhook / refresh_click / OCR 频率
   - 启动持续监控
2. Agent 通过 Ayes skill 或本地工具，直接读取：
   - 当前监控状态
   - 最近截图证据
   - 近期事件
   - 短期记忆
   - 问答结果
3. 人类只在以下场景回到工作台：
   - 调整目标与 ROI
   - 校验最近真实读屏结果
   - 排查为什么没命中、没告警、没回答出来

这意味着：

- Web 工作台不是最终主使用面
- skill / API / CLI 才是后续真正面向 Agent 的第一入口
- Web 工作台的产品职责必须收敛到“配置 + 核验 + 排查”
