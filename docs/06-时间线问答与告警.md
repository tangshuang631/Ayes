# 06 时间线问答与告警

## 1. 时间线问答目标

第一阶段必须支持用户基于最近 5-15 分钟时间线进行提问。

核心问题包括：

- 最近 5 分钟发生了什么
- 最近 10 分钟有哪些异常
- 某个窗口什么时候发生了关键变化
- 为什么当前界面会变成这样
- 哪次变化最值得关注
- 这几分钟某个软件有没有弹窗报错
- 今天某个股票是跌了还是涨了，最低大概是什么时候

同时，长期监控场景下还应支持基于轻量长期时间线回答更粗粒度的问题，例如：

- 今天这个监控目标大致发生过哪些关键变化
- 最近几个小时出现过几次异常
- 哪些时间段最活跃

问答必须同时服务两种任务模式：

- 目标触发监控：回答触发目标是否出现、何时出现、证据是什么
- 观察型监控：在没有触发目标的情况下，回答最近发生了什么

并且问答必须支持“围绕当前监控目标的隐式上下文提问”：

- 用户即使没有重复说明监控对象
- 只要问题与当前监控进程、窗口或屏幕相关
- Ayes 也应自动带入当前监控上下文进行检索和回答

## 2. 问答路径

建议问答路径如下：

1. 接收问题
2. 将问题转成检索条件
3. 使用关键词 + 向量混合检索从时间线取回候选事件
4. 补充必要上下文
5. 输出结构化回答

## 3. 问答限制

第一阶段不应采用以下做法：

- 每次问答重新全量 OCR
- 每次问答重新扫描所有截图
- 完全依赖大模型即兴发挥

## 4. 告警目标

第一阶段标准告警出口为企业微信 webhook。

告警只在目标触发监控模式下默认启用。观察型监控默认不主动发送 webhook，除非用户后续追加触发条件。

告警发送必须由 Ayes 后台服务直接承担，不能依赖已安装 skill 的智能体是否此刻在线回复。

完整企业微信 webhook 策略见：

- [14-企业微信Webhook告警策略.md](/Users/apple/Desktop/2026/Ayes/docs/14-企业微信Webhook告警策略.md)

## 5. 告警触发条件

建议包括：

- 命中监控意图
- 事件优先级达到阈值
- 未命中去重限制
- 未命中冷却限制
- 当前 watch spec 开启告警

## 6. 告警内容

告警内容建议包含：

- 时间
- 进程名
- 窗口标题
- 事件摘要
- 关键 OCR 文本
- 事件优先级
- 事件引用 ID

对于“商品有货时通知我”这类任务，告警内容还应包含：

- 触发目标摘要
- 命中的文本或视觉证据
- 是否由刷新点击后产生的变化触发

这些只是示例，Ayes 的告警内容设计应适用于更广泛的通用视觉条件监控任务。

## 7. 第一阶段结论

问答和告警都必须建立在时间线事件之上，而不是建立在原始截图全量重跑之上。

并且时间线必须分层：

- 短期详细记忆用于高细节回放
- 长期轻量记忆用于长时监控总结

目标触发监控和观察型监控共用同一套时间线模型，差异只在于是否配置触发条件、告警和受控刷新点击。

事件字段以 [11-事件模型契约.md](/Users/apple/Desktop/2026/Ayes/docs/11-事件模型契约.md) 为准。

记忆存储和清理策略以 [12-记忆存储设计.md](/Users/apple/Desktop/2026/Ayes/docs/12-记忆存储设计.md) 为准。

问答检索路径以 [13-问答检索路径.md](/Users/apple/Desktop/2026/Ayes/docs/13-问答检索路径.md) 为准。

## 8. 当前阶段补充要求

当前阶段的问答、时间线和告警不能只通过 CLI 或 JSON 文件观察。

必须补充：

- 前端中的近期事件视图
- 前端中的短期记忆视图
- 前端中的问答输入与回答区域
- 前端中的告警状态或最近告警记录
- 前端中的运行日志入口
- agent / skill 侧的最近告警读取入口

这样用户才能真正核验：

- 是否抓到了变化
- OCR 是否识别到了关键文本
- 问答为什么这样回答
- 为什么某次没有命中目标
- 为什么某次没有触发 webhook
