# 16 v1 项目目录结构

## 1. 文档目标

本文件定义 Ayes v1 的项目目录结构、模块边界和运行期文件布局。

目标是避免后续实现时：

- 代码散落
- 数据目录混乱
- 配置与运行产物混放
- 测试目录无边界

## 2. 总体原则

v1 目录结构应满足：

- Python 作为核心实现语言
- 核心能力按模块拆分
- `src/ayes/` 内部必须继续按功能和结构拆成多个文件，避免把核心逻辑堆进少量大文件
- 配置、数据、日志、运行时文件分离
- 可支持本地服务、CLI 和后续 skill 接入
- 文档、源码、测试、运行产物有清晰边界
- 源码、配置、脚本和文档统一使用 `UTF-8` 编码

## 3. 建议顶层结构

```text
Ayes/
  docs/
  src/
  tests/
  scripts/
  skills/
  data/
  runtime/
  web/
  .gitignore
  README.md
  pyproject.toml
```

## 4. docs

`docs/` 用于项目规则、正式开发文档和临时实施文档。

当前规则不变：

- 正式开发文档放 `docs/`
- 临时文档放 `docs/temp/`

## 5. src

`src/` 用于核心实现代码。

即使核心代码放在 `src/ayes/`，也必须严格按功能和结构拆分成多个文件和子模块，方便后续迭代、排错和测试。

建议结构：

```text
src/ayes/
  __init__.py
  config/
  app/
  targets/
  capture/
  actions/
  detect/
  ocr/
  match/
  events/
  memory/
  alert/
  query/
  api/
  cli/
  utils/
  logs/
```

## 6. 核心模块划分

### 6.1 `config/`

负责：

- 读取和校验 `watch spec`
- 读取环境变量
- 管理默认配置

### 6.2 `app/`

负责：

- 服务启动入口
- 任务生命周期编排
- 定时循环和调度

### 6.3 `targets/`

负责：

- 进程、窗口、屏幕目标发现
- 目标过滤
- 可观测性判定
- 候选目标数据结构

### 6.4 `capture/`

负责：

- 屏幕或窗口截图
- 采样频率控制
- 截图失败状态记录
- 统一 `CaptureFrame` 结构

### 6.5 `actions/`

负责：

- 受控刷新点击
- 点击节流、冷却和暂停恢复
- 点击审计事件

### 6.6 `detect/`

负责：

- 差分检测
- ROI 检测
- 去重和静态区域跳过
- 变化阈值判定

### 6.7 `ocr/`

负责：

- OCR Provider 抽象
- PaddleOCR Provider
- 后续 RapidOCR / Tesseract Provider 预留位
- OCR 结果归一化

### 6.8 `match/`

负责：

- 关键词匹配
- 数值阈值规则
- 向量语义匹配
- `watch_intent` 命中判断

### 6.9 `events/`

负责：

- 事件结构定义
- 事件工厂
- 审计事件生成

### 6.10 `memory/`

负责：

- 短期详细记忆写入和清理
- 长期轻量记忆写入和清理
- 证据文件生命周期管理

### 6.11 `alert/`

负责：

- 企业微信 webhook 发送
- 去重
- 冷却
- 失败处理

### 6.12 `query/`

负责：

- 时间范围解析
- 混合检索
- 回答结构生成
- 当前监控目标隐式上下文处理

### 6.13 `api/`

负责：

- 本地 HTTP 接口
- 供后续 skill / tool 调用

### 6.14 `cli/`

负责：

- 本地命令行入口
- 启动、停止、查询、测试命令

### 6.15 `utils/`

负责：

- 通用工具函数
- 时间处理
- 序列化
- 文件工具

### 6.16 `logs/`

负责：

- 结构化日志写入
- 日志分类
- 日志读取接口
- 运行状态调试辅助

## 6.17 `web/`

`web/` 用于本地 Web 工作台前端。

要求：

- 前端必须服务于真实监控、事件查看、记忆查看、日志查看和问答测试
- 默认采用简洁一体化工作台布局
- 避免卡片化堆叠
- 通过本地 API 与 `src/ayes/` 服务层交互

## 6.18 `skills/`

`skills/` 用于仓库内维护面向 Codex / OpenClaw / 其他智能体的正式 skill 产物。

要求：

- 每个 skill 至少包含：
  - `SKILL.md`
  - `agents/openai.yaml`
- skill 只承载触发条件、调用顺序、失败回退和交互约定
- 不允许把核心业务逻辑直接塞进 skill 文档
- 需要复用的本地工具、安装脚本和服务控制入口，应放在：
  - `src/ayes/cli/`
  - `scripts/`

建议结构：

```text
skills/
  final/
    ayes-local/
    SKILL.md
    agents/
      openai.yaml
```

## 6.19 拆分约束

第一阶段明确禁止以下情况：

- 将窗口发现、截图、OCR、匹配、告警、问答混在同一个大文件
- 将多个不相干的数据结构塞进同一个实现文件
- 为了省事把试验代码直接放进核心模块

原则：

- 一个文件只承担一个清晰职责
- 共享契约放在专门模块
- 平台相关实现与平台无关接口分离
- 便于后续单独修复某一层而不影响全部链路

## 7. tests

`tests/` 用于自动化测试。

建议结构：

```text
tests/
  config/
  targets/
  capture/
  actions/
  detect/
  ocr/
  match/
  events/
  memory/
  alert/
  query/
  api/
  logs/
  cli/
  web/
  skills/
```

要求：

- 测试目录应与 `src/ayes/` 的核心模块边界对应
- 关键契约文档对应的模块必须有契约测试

## 8. scripts

`scripts/` 用于：

- 本地调试脚本
- 一次性验证脚本
- 环境检查脚本
- skill 安装辅助脚本
- 本地后台启动辅助脚本

例如：

- 窗口发现验证
- 截图能力验证
- OCR provider 验证
- webhook 发送测试

## 9. data

`data/` 用于持久化数据。

建议结构：

```text
data/
  app.db
  evidence/
  summaries/
```

说明：

- `app.db`：SQLite 主库
- `evidence/`：截图、ROI、OCR 原始引用
- `summaries/`：可选摘要缓存或导出数据

## 10. runtime

`runtime/` 用于运行时易变文件。

建议结构：

```text
runtime/
  logs/
  pids/
  cache/
  tmp/
```

说明：

- `logs/`：运行日志
- `pids/`：进程 pid 文件
- `cache/`：临时检索缓存
- `tmp/`：临时图像或处理中间文件

## 11. 配置文件

顶层建议保留：

- `pyproject.toml`
- `.gitignore`
- `README.md`

其中：

- `pyproject.toml`：Python 依赖和工具配置
- `.gitignore`：忽略 `data/`、`runtime/` 中的运行产物
- `README.md`：启动方式和最小使用说明

## 12. 编码要求

v1 目录内所有源码、配置、文档和脚本应统一使用 `UTF-8` 编码。

特别是：

- 中文文档
- 中文告警模板
- 中文 OCR 文本
- 中文日志

都必须避免乱码。

## 13. 第一阶段结论

v1 项目结构必须优先支持：

- 本地常驻服务
- 本地 CLI / HTTP
- 事件与记忆持久化
- 后续 skill 接入

后续实现时应严格围绕本目录结构展开，避免把验证脚本、运行产物和核心源码混在一起。
