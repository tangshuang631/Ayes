# Ayes 第一阶段实施方案

- [ ] 1. 明确第一阶段技术栈与运行形态
  - 目标：确定 Ayes v1 的语言、运行方式、进程监控方案、OCR 方案、向量检索方案、存储方案、企业微信推送方案。
  - 产出：一份可执行的技术选型结论，回写到正式开发文档或新增正式模块文档。

- [ ] 2. 验证指定进程下窗口发现能力
  - 目标：验证当前系统环境下，是否可以稳定枚举指定进程关联窗口，并拿到窗口身份、标题、层级、最小化/隐藏等状态。
  - 产出：窗口发现能力结论、限制说明、候选实现路径。

- [ ] 3. 验证窗口采集可行性
  - 目标：验证前台窗口、后台窗口、被遮挡窗口、最小化窗口的像素采集能力边界。
  - 产出：可采集状态矩阵，以及“状态可观测”和“像素可采集”的差异说明。

- [ ] 4. 确定采样与变化检测链路
  - 目标：确定采样频率、帧差分方式、ROI 检测方式、去重策略。
  - 产出：变化检测最小链路设计。

- [ ] 5. 确定 OCR 处理链路
  - 目标：确定 OCR 引擎、文本清洗规则、文本块切分规则、与窗口/区域绑定的结构格式。
  - 产出：OCR 输入输出约定。

- [ ] 6. 确定轻量视觉标签策略
  - 目标：明确第一阶段标签集合、标签触发规则、优先级映射。
  - 产出：`dialog`、`error_like`、`status_change` 等标签的初版判定方案。

- [ ] 7. 确定语义匹配方案
  - 目标：明确 embedding 模型、向量库存储方式、事件与 watch intent 的匹配流程。
  - 产出：语义匹配最小实现设计。

- [ ] 8. 完成 Watch Spec 初版定义
  - 目标：把用户自然语言监控目标转成统一可执行配置结构。
  - 产出：可用于实现的 `watch spec` 正式定义。

- [ ] 9. 完成事件模型初版定义
  - 目标：明确事件字段、证据引用、优先级、可观测状态、语义匹配结果。
  - 产出：正式事件 JSON 结构。

- [ ] 10. 确定短时时间线存储设计
  - 目标：明确最近 5-15 分钟事件如何存、如何查、如何清理。
  - 产出：时间线存储结构与清理策略。

- [ ] 11. 确定问答检索路径
  - 目标：定义“最近几分钟发生了什么”“为什么变成现在这样”的检索和摘要流程。
  - 产出：问答链路设计。

- [ ] 12. 确定企业微信 webhook 告警策略
  - 目标：明确触发条件、去重、冷却、消息模板和失败重试策略。
  - 产出：告警策略设计。

- [ ] 13. 规划 v1 项目目录结构
  - 目标：在正式实现前明确代码目录、模块边界、配置位置、日志位置、测试目录。
  - 产出：v1 代码结构草案。

- [ ] 14. 拆解第一批开发任务
  - 目标：将 v1 拆成可执行的小任务，供后续逐项开发。
  - 产出：开发任务清单或正式实施计划文档。

- [ ] 15. 完成文档回写检查
  - 目标：确认上述结论已同步到正式开发文档，不把临时结论只留在 `docs/temp`。
  - 产出：正式文档更新记录。

- [ ] 16. 开发完成后重命名本文件
