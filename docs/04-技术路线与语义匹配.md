# 04 技术路线与语义匹配

## 1. 第一阶段固定路线

第一阶段固定采用：

> OCR + 向量语义匹配 + 轻量视觉标签

## 2. 为什么当前不以 YOLO 为主线

第一阶段核心问题是：

- 过去几分钟发生了什么
- 哪些变化值得关注
- 哪些变化应触发告警
- 当前界面为什么会变成这样

这些问题在第一阶段更依赖：

- OCR 文本变化
- 窗口标题变化
- 区域内容变化
- 轻量标签
- 时间顺序

因此 YOLO 不是 MVP 的基础能力。

## 3. OCR 层职责

OCR 层负责：

- 提取变化区域文字
- 提取标题、正文、按钮文案、数值和表格片段
- 进行清洗、分块和归一化
- 将 OCR 文本与窗口、区域、时间绑定

## 4. 轻量视觉标签

第一阶段采用轻量标签，而不是复杂检测模型。

建议标签包括：

- `dialog`
- `error_like`
- `status_change`
- `form_change`
- `table_delta`
- `notification_like`
- `captcha_like`

标签来源可以包括：

- OCR 关键词
- 规则判断
- 区域变化形态
- 窗口结构信号

## 5. 语义匹配职责

语义匹配层负责：

- 对事件文本、摘要、标题、标签做 embedding
- 对监控意图做 embedding
- 判断事件是否命中重点关注内容
- 支持基于语义的问题检索最近时间线

## 6. 用户自然语言到 Watch Spec

用户可以自然语言描述要关注的变化，但 Ayes 不直接执行自然语言。

推荐流程：

1. 用户输入自然语言监控目标
2. 上层 Agent 或配置编译器转换为 `watch spec`
3. Ayes 根据 `watch spec` 执行

## 7. 第一阶段结论

第一阶段以：

- 规则
- OCR
- embedding 检索
- 轻量标签

作为主识别链路。

YOLO 放入第二阶段增强项。
